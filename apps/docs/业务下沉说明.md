# 文档服务：业务请留在调用方

`docs` 只保存和查询文档、分类。站点品牌、默认栏目、色板、前台路径和草稿语义不再写在这个服务里。请在你们自己的服务中保留这些规则，并按下面的契约调用。

已有数据行不会被改写。库里原来的 `app_code`、色值、`nav` 仍原样可读。变的是：**新请求不再替你们填博客默认值**。

## 请你们自己保留的内容

这些曾经写死在文档服务里，现已删除。请放到你们的服务（或前端）中：

- 默认应用编码 `blog`。每次请求都要自己带 `appCode`。
- 默认分类「生活 / 编程 / 闲聊」，以及缺省分类 slug `life`。
- 站点关于页：站名、头像、技能（例如 React / TS、摄影、咖啡）。接口 `GET/PUT /docs/site` 已移除。
- 色板枚举：`app-pink`、`warm-peach-pink`、`app-yellow` 等。色值的含义由你们定义。
- 前台保留路径（`notes`、`about`、`admin` 等）和保留标签名（「笔记」「关于」「全部」「标签」）。
- 路径别名 `/docs/posts`。对外只保留 `/docs/documents`。
- 字段名 `pageKind`。文档形态只使用 `kind`。
- 布尔字段 `draft`、查询参数 `includeDrafts`。可见性只使用 `visibility=public|private`。
- `tree=1` 表示「我的工作区」。树形视图和工作区范围要分开传。
- 文档形态 `kb`。本服务的 `kind` 只有 `article`，不会再把 `kb` 收成 `article`。

## 调用时必须改的地方

| 原来 | 现在 |
| --- | --- |
| 不传 `appCode`，服务默认成 `blog` | 必填。缺省或格式不对返回 `400 INVALID_APP_CODE`。格式：字母开头，2–32 位，允许字母、数字、`_`、`-` |
| `POST /docs/posts` 等 `/docs/posts/*` | 改为 `/docs/documents` 下的同一路径 |
| 请求/响应字段 `pageKind` | 改为 `kind`。目前只接受 `article`。不传则按 `article` 存储 |
| 不传分类 `type`，或分类不存在时落到 `life` | 不再代选分类。请传已存在的分类 slug；对不上就存空字符串 |
| 分类 `color` 必须是内置色板之一 | 任意 token：1–32 位，字母数字、`_`、`-`。未知色值原样返回，不再改成 `app-yellow` |
| 不传 `nav` 时默认 `true`（出现在导航） | 创建时不传则为 `false`。更新时不传则保持原值。是否展示由你们解释 |
| `draft=true/false`，或 `includeDrafts=1` | 只传 `visibility`。全量读取用 `scope=all`，必须带 `x-docs-key`。详情要看全部可见性时，同样带密钥并传 `mode=any` |
| 只传 `tree=1` 就进入「我的」 | 工作区必须传 `scope=mine`（用户 JWT）。`tree=1` 或 `view=tree` 只决定是不是树形结果 |
| 共享库里 `kind=kb`、用 `draft` 表示发布、`app_code` 为空 | 启动搬运会跳过这些行，不会改写成 `article` / `blog`。请你们自行迁移 |

## 仍然由文档服务提供

- 按 `appCode` 隔离的文档和分类存储
- 文档字段：标题、slug、摘要、封面、Editor.js 正文、作者、父子树、`visibility`、发布时间
- 分类字段：名称、slug、说明、色值字符串、`kind`、`nav` 布尔、排序。改 slug 时同步文档上的分类
- 列表范围：`scope=public|feed|mine|all`
- 网关鉴权：公开读不强制登录；写操作需要用户 JWT 或 `x-docs-key`

删除某个应用下最后一个分类时，服务会补一条 `slug=uncategorized`、名称「未分类」、色值 `neutral` 的占位分类，避免文档失去分类引用。这不是产品栏目，业务分类请自行创建。

## 示例

```bash
# 公开列表。appCode 用你们自己的编码
curl 'http://127.0.0.1:3000/docs/documents?appCode=blog&scope=public'

# 当前用户的工作区
curl -H "Authorization: Bearer <token>" \
  'http://127.0.0.1:3000/docs/documents?appCode=blog&scope=mine'

# 新建文档。kind、分类、色值都由你们传入
curl -X POST http://127.0.0.1:3000/docs/documents \
  -H "Authorization: Bearer <token>" \
  -H 'Content-Type: application/json' \
  -d '{
    "appCode": "blog",
    "title": "标题",
    "kind": "article",
    "type": "life",
    "visibility": "private",
    "body": { "time": 0, "blocks": [] }
  }'

# 分类色值和导航由你们决定
curl -X POST http://127.0.0.1:3000/docs/categories \
  -H "Authorization: Bearer <token>" \
  -H 'Content-Type: application/json' \
  -d '{
    "appCode": "blog",
    "name": "生活",
    "slug": "life",
    "color": "app-blue",
    "kind": "article",
    "nav": true
  }'
```

`appCode=blog`、分类「生活」、色值 `app-blue` 可以继续用，但必须由你们的请求带上，文档服务不再内置。
